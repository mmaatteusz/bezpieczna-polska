# Audyt projektu — 2026-09-26

Ten dokument opisuje aktualny stan projektu po naprawie Railway autodeploy, runtime audytu i niezawodności aktualizacji APK.

## Repo i CI

- aktywny branch produkcyjny: `main`,
- Android jest główną platformą rozwojową,
- backend, Flutter, PostGIS i kontrakty źródeł mają automatyczne testy,
- preview Android ma osobny stały signer,
- istnieje blokujący test aktualizacji APK przez Android PackageManager,
- production release pipeline buduje podpisany AAB/APK dopiero dla release/manualnego uruchomienia.

`android-release` i opcjonalny PSP `live-source` są celowo pomijane przy zwykłym pushu do `main`; nie są to błędy CI.

### WCZK

RSO jest krajowym kanałem publikacji komunikatów WCZK. Rejestr obejmuje 16 województw, ale nie tworzymy 16 sztucznych niezależnych źródeł. Osobny direct adapter działa dla Podkarpackiego jako dodatkowy oficjalny mirror tego samego wydawcy.

### UkraineAlarm

Adapter, model, UI i endpointy istnieją, ale produkcja nie ma obecnie zweryfikowanego `UKRAINE_ALARM_API_KEY`.

Stan produkcyjny:

```text
UkraineAlarm live: NOT_CONFIGURED
```

Funkcja nie może wyglądać w UI na aktywną, dopóki live source nie zostanie skonfigurowane i przetestowane.

### Push

Kod zawiera:

- Firebase/APNs adaptery,
- rejestrację urządzenia,
- rotację tokenu,
- preferencje,
- szyfrowanie tokenów,
- deduplikację,
- outbox,
- retry i permanent failure.

Produkcja nie ma jeszcze kompletnej konfiguracji providerów i sekretów.

```text
push code: gotowy
push production delivery: NOT_CONFIGURED
```

### PAA measurements i CSIRT GOV

`PAA_MEASUREMENTS` pozostaje świadomie wyłączone, ponieważ nie ma zweryfikowanego stabilnego kontraktu publicznych pomiarów.

`CSIRT_GOV` pozostaje wyłączone, ponieważ oficjalny publiczny kanał nie daje obecnie użytecznego bieżącego feedu dla aplikacji.

## Android

Identyfikatory pakietów:

```text
development: pl.bezpiecznapolska.dev
preview:     pl.bezpiecznapolska.preview
production:  pl.bezpiecznapolska
```

Preview ma stały signer i monotoniczny `versionCode`.

Automatyczny test emulatora potwierdza:

1. instalację starszego preview,
2. zapis danych aplikacji,
3. `adb install -r` nowszego APK,
4. zachowanie danych,
5. odrzucenie downgrade przez `INSTALL_FAILED_VERSION_DOWNGRADE`.

To zamyka wcześniejsze ryzyko konieczności odinstalowywania aplikacji pomiędzy kolejnymi preview.

## Funkcje istniejące w kodzie, ale jeszcze niewystawione / niewdrożone

### Stopnie alarmowe

Backend i dane są aktywne. Flutter ma gotowy `SecurityLevelsPanel`, ale obecna główna nawigacja go nie wystawia.

### PAA

Komunikaty PAA działają. `RadiationPanel` istnieje, ale nie jest obecnie osobnym elementem głównej nawigacji. Pomiary stacji pozostają wyłączone.

### Ukraina

`UkrainePanel` i `UkraineMap` istnieją i mają testy, ale produkcyjne live jest wyłączone z powodu braku klucza. Obecny polski ekran mapy nie powinien udawać aktywnego UkraineAlarm.

### Push

Ekran ustawień jest podłączony, ale bez skonfigurowanego providera aplikacja ma jawnie komunikować brak produkcyjnej wysyłki.

## Offline

Pakiety offline zawierają dane bezpieczeństwa, schronienia i potrzebny stan regionu. Nie zawierają pełnego zestawu kafli mapowych. Dlatego offline oznacza LAST KNOWN GOOD dla danych, a nie pełną nawigacyjną mapę offline.

## Admin

Backend ma chronione endpointy administracyjne, ale nie ma jeszcze docelowego panelu z:

- użytkownikami,
- rolami,
- MFA,
- krótkimi sesjami uprzywilejowanymi,
- pełnym workflow moderacji.

Bearer `ADMIN_TOKEN` nie jest docelowym publicznym panelem administracyjnym.

## Co jest dobre

- last-known-good zamiast kasowania danych po błędzie,
- jawny source health,

## Wniosek

Projekt nie jest już szkieletem. Backend produkcyjny, większość źródeł, mapy, offline i Android preview są funkcjonalne oraz testowane. Główne ryzyko przed publicznym wydaniem nie leży już w kolejnym redesignie UI, tylko w produkcyjnym podpisie, dystrybucji, push, polityce prywatności i domknięciu funkcji, które istnieją w kodzie, ale nie są jeszcze wystawione użytkownikowi.
